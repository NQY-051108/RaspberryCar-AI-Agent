# 树莓派小车摄像头采集操作手册

本文用于树莓派端开启摄像头、电脑端弹出实时画面，并在预览时将图片保存到树莓派。当前流程使用一个服务器进程独占摄像头，再把同一帧同时用于预览和存图。

## 先记住这三点

1. 树莓派端运行 `realtime_stream_server.py`，电脑端运行 `realtime_stream_client.py`。
2. 不要同时启动 `capture.py`、旧版小R拍照程序或另一个摄像头预览程序；`/dev/video0` 同一时间通常只能由一个程序打开。
3. 服务器只有在电脑客户端连接后才开始读取画面和保存图片。电脑关掉预览后，服务器会等待重连，期间不会继续存图。

## 一、每次采集的标准启动顺序

### 1. 树莓派端：SSH 登录后确认摄像头和 IP

```bash
hostname -I
ls -l /dev/video*
v4l2-ctl --list-devices
```

如果 `v4l2-ctl` 不存在，安装一次即可：

```bash
sudo apt update
sudo apt install -y v4l-utils
```

已知摄像头常用 `/dev/video0`，但如果命令显示的设备节点不同，先按后文排查；服务器的 `--camera 0` 对应 `/dev/video0`，`--camera 1` 对应 `/dev/video1`。

### 2. 树莓派端：创建本次批次目录并启动预览+保存服务

下面示例把路线名写入目录名；将 `road_A` 改成实际路线或采集批次：

```bash
ROUTE="road_A"
SAVE_DIR="$HOME/car_data/${ROUTE}_$(date +%Y%m%d_%H%M%S)"
echo "本次保存目录：$SAVE_DIR"

python3 ~/RaspberryCar-AI-Agent/camera_stream/realtime_stream_server.py \
  --camera 0 \
  --width 640 \
  --height 480 \
  --fps 10 \
  --port 9000 \
  --save-dir "$SAVE_DIR" \
  --save-interval 0.5
```

启动成功时，SSH 窗口应显示类似信息：

```text
Camera: /dev/video0, 640x480, ...
Listening on 0.0.0.0:9000
Start the Windows client now.
Local JPEG saving: /home/pi/car_data/road_A_YYYYMMDD_HHMMSS
```

保持这个 SSH 窗口运行。`--save-interval 0.5` 表示大约每 0.5 秒保存一张（约 2 张/秒），不是摄像头帧率。若想每秒一张改为 `1.0`；若想每 0.2 秒一张改为 `0.2`。

启动输出还会显示服务进程号，例如：

```text
Server PID: 1234
```

### 运行中暂停和恢复保存

预览窗口可以保持打开，只暂停图片写入。在树莓派另开一个 SSH 窗口，把 `1234` 换成实际的 `Server PID`：

```bash
kill -USR1 1234
```

服务器终端显示 `Image saving paused` 后，画面仍会继续更新，但 JPG 和 `metadata.csv` 不再增加。需要继续采集时，再执行一次：

```bash
kill -USR1 1234
```

服务器终端显示 `Image saving resumed` 后恢复保存。不要启动第二个摄像头程序；暂停/恢复只切换当前服务器的写盘开关。

### 3. Windows 端：启动桌面实时可视化窗口

在仓库根目录的电脑 PowerShell 中运行。下面的 IP 按当前小车常用地址填写；如果第一步 `hostname -I` 显示了新地址，要替换成新地址：

```powershell
py camera_stream\realtime_stream_client.py --host 192.168.88.100 --port 9000
```

程序会弹出 `Raspberry Pi Camera` 窗口，并显示接收 FPS 和帧数。初次使用电脑端依赖时再安装一次：

```powershell
py -m pip install opencv-python numpy
```

先启动树莓派服务器，再启动 Windows 客户端。可在 PowerShell 先测试网络端口：

```powershell
Test-NetConnection 192.168.88.100 -Port 9000
```

`TcpTestSucceeded : True` 表示电脑能连到服务端口。

## 二、怎么确认正在采集

同时满足以下现象，才能确认预览和存图工作正常：

- Windows 的 `Raspberry Pi Camera` 窗口有画面，FPS 和帧数持续增加。
- 树莓派服务器终端打印了本次 `Local JPEG saving` 路径。
- WinSCP 打开该打印出的目录后，能看到 `frame_*.jpg` 和 `metadata.csv`；刷新目录时 JPG 数量增加。

图片保存在树莓派本地，不会自动出现在电脑的 WinSCP 左侧目录。用 WinSCP 进入终端打印的完整目录后，可将图片下载到电脑。服务器保存的 CSV 记录图片序号、文件名、时间和分辨率；路线/批次目前通过目录名区分。

查看树莓派磁盘空间：

```bash
df -h "$HOME"
```

## 三、正常停止和重新开始

1. 电脑实时窗口按 `q` 或 `Esc`，关闭客户端。
2. 回到运行服务器的 SSH 窗口按 `Ctrl+C`，服务器退出并释放摄像头。
3. 下次采集重新运行“创建目录并启动服务器”命令，会生成新的时间戳目录。

如果只关闭 Windows 窗口，服务器会继续运行并等待客户端重连，但断开期间不会保存图片。完成采集后仍要在 SSH 窗口按 `Ctrl+C` 结束服务器。

如果需要立即停止所有采集和预览，直接在运行服务器的 SSH 窗口按 `Ctrl+C`。这会释放摄像头；下次按“每次采集的标准启动顺序”重新开始。

## 四、当前错误：`Cannot open camera index 0`

这个错误发生在服务器打开摄像头时；仅凭错误文本不能判断具体是“摄像头被占用”“设备编号不对”“设备断开”还是“权限不足”。按以下顺序检查：

### 1. 先找占用摄像头的进程

在树莓派另开一个 SSH 窗口执行：

```bash
pgrep -af 'realtime_stream_server|capture.py|camera_capture.py'
sudo fuser -v /dev/video0
```

如果有输出，核对 PID 和命令，回到对应 SSH 窗口按 `Ctrl+C` 正常停止旧的采集/预览进程，然后再启动本手册中的服务器。不要不加区分地结束所有 `python3` 进程，因为其中可能有底盘控制程序。

### 2. 确认节点编号和连接

```bash
ls -l /dev/video*
v4l2-ctl --list-devices
```

确认 USB 摄像头列出的节点。如果实际可用设备是 `/dev/video1`，启动时将 `--camera 0` 改为 `--camera 1`。重新插好摄像头 USB 接头后再查一次。

### 3. 检查用户权限

```bash
id
ls -l /dev/video0
```

若设备归属 `video` 组而当前用户不在该组，可执行一次：

```bash
sudo usermod -aG video "$USER"
```

然后完全退出 SSH 并重新登录，再试启动。若改组前后现象不明确，先不要同时用 `sudo` 启动多个采集程序。

### 4. 如果摄像头已打开但端口启动失败

若错误变成 `Address already in use`，表示 TCP 9000 已被服务占用。这和摄像头打开失败是两类问题。先查已有服务器：

```bash
pgrep -af realtime_stream_server.py
```

若已有服务正在运行，使用它对应的 Windows 客户端；或者回到旧服务器 SSH 窗口按 `Ctrl+C`，再重开。不要重复启动第二个实例抢摄像头。

## 五、网络或窗口问题

- `Connection refused`：先确认树莓派服务器已显示 `Listening on 0.0.0.0:9000`，再确认 IP 和端口正确。
- `TcpTestSucceeded : False`：电脑和树莓派需要处于可互通的同一局域网；重新运行 `hostname -I` 检查树莓派 IP。
- 窗口黑屏或画面冻结：确认服务器终端无摄像头读取错误；检查 USB 连接。可降低负载，将服务端参数改为 `--width 320 --height 240 --fps 8`。
- 延迟较大：先降低分辨率/FPS，或确保电脑和树莓派网络信号稳定。
- 摄像头打不开：退出旧预览/拍照程序后再试，不要并行运行 `capture.py`。

## 六、采集文件位置

每次服务器启动时都会打印完整保存路径，例如：

```text
/home/pi/car_data/road_A_20261030_143000
```

在 WinSCP 右侧输入或打开该完整路径。目录内是 JPG 图片和 `metadata.csv`。建议按路线、日期和不同光照条件分批采集；每次重启服务器都会新建批次目录，避免把不同批次混在一起。

## 当前程序能力边界

- 本程序仅负责摄像头预览和存图，不控制电机，也不会让小车自主行驶。
- 当前预览/保存使用同一编码后的 JPEG 帧，降低重复读取摄像头的风险。
- 带 `--save-dir` 运行时默认保存开启；`SIGUSR1` 只暂停/恢复 JPG 与 CSV 写入，实时视频不受影响。
- Windows 客户端断开时服务器不会继续采集；如需断开电脑后仍连续录制，需要另做后台采集/断线持续存图功能。
- 请在安全、受控的环境中采集；如果小车正在移动，先限速并准备实体急停。
